# VietDub AI V0.1 架构与阶段边界

## 仓库检查
初始目录为空，未发现现有代码或 AGENTS.md。采用 frontend / backend 单仓库。

## Phase 1
浏览器 → Next.js 同源 /api 代理 → FastAPI 路由 → 服务 → Repository / SQLAlchemy → PostgreSQL。
上传服务流式读取 1 MiB 分块，限制 512 MiB，检查扩展名及 ftyp 文件头；随机服务端文件名防止路径穿越。完整媒体有效性由后台 FFprobe 验证。原始文件 SHA-256 入库，每集仅允许一个原片；条件 UPDATE 保证并发竞争只有一个上传成功。原片不对外直接暴露，删除记录保留文件。

Job 与原片路径同事务写入 PostgreSQL，充当持久化发件箱。Celery beat 每 15 秒扫描 queued 与过期 running，通过 Redis 投递；条件 UPDATE 原子认领并设置 2100 秒租约。任务硬时限 1950 秒，媒体命令总超时小于租约。重复投递不重复处理成功任务；进程死亡后租约到期可恢复。失败保留简化错误与次数，人工重试。此版本只支持一个 beat 实例。

FFprobe 获取整数毫秒时长、分辨率、视频编码，要求视频和音频、最长 6 小时。FFmpeg 从第一条音轨输出单声道 16 kHz PCM WAV；临时输出成功后原子替换。命令不经过 shell，协议仅允许本地文件。Docker 中需进一步以资源配额约束不可信媒体的 CPU / 内存消耗。

分析成功后人工确认媒体；该检查点不会触发任何后续 AI 操作。数据库迁移显式创建表与索引。API 响应隐藏磁盘路径。

## 后续设计（未实现）
Segment 使用 start_ms / end_ms 整数与 end_ms > start_ms 约束；保存原文、译文版本、speaker_id。Speaker 保存人工修正；VoiceMapping 保存 provider / voice_id。ASR、Translation、TTS 适配器通过 Protocol 隔离，当前只有离线 mock 契约，不挂接生产流程。翻译上下文将包含项目术语表、前后对话及角色设定；TTS 按分段版本幂等生成；渲染基于审批版本快照。未来分别增加转写、翻译、配音与成片人工审批。

## 密钥与部署边界
Phase 1 不需要 AI 密钥，也不发起供应商请求。未来密钥由部署 secret manager 注入 worker，不入数据库、不进入 NEXT_PUBLIC、不写日志或版本库。.env 被忽略；示例无真实密钥。当前无身份鉴权，为本机受信单用户开发环境，Compose 只绑定回环地址，数据库及 Redis 不发布端口。公开部署前必须增加认证、租户隔离、TLS、反向代理请求体限制、上传配额、审计与备份。

## 已知限制
无视频预览 / WAV 下载、上传进度、分片续传、分页界面与自动清理；multipart 解析器会先暂存到磁盘，ASGI 中间件限制请求总量为 513 MiB，文件本身限制为 512 MiB，仍应在入口设置请求体限制和配额。容器损坏可上传成功后后台失败；修正原片须新建剧集。文件与数据库不具备跨系统原子事务，崩溃可能遗留孤儿文件，需后续清理工具。未启用数据库行级隔离或跨租户权限。ORM 单元测试使用 SQLite，不能替代 PostgreSQL 并发集成测试。任务列表仅显示最近 100 条，旧剧集的任务状态需通过任务 ID 查询。
